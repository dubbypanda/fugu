Codex is now pinned to 0.149.1

Fugu now targets Codex 0.149.1. The launcher will offer to switch your Codex to it, and your existing Fugu configs and API key carry over unchanged.

This spans several upstream releases (0.148 and 0.149): it adds Markdown conversation export (/export), session forking with archive and restore, an interactive "codex agents" dashboard, working-directory commands (/cd, /pwd, /cwd) and a "codex queue" for messaging existing sessions, richer Vim editing, thread cost and credit estimates in /status, a built-in Amazon Bedrock provider, and asynchronous hooks that can call MCP tools. None of that changes how Fugu works — you reach the same Fugu models through the same Sakana API, with the same stream-resilience and safety settings as before.

Nothing is required on your part, and Fugu behaves the same as before. The Fugu config still pins remote plugins off ("remote_plugin = false" in the [features] block of ~/.codex/fugu.config.toml), and now also pins Codex 0.148.0's unbounded connection retries off ("unbounded_connection_retries = false") so a down or misconfigured endpoint fails with a bounded, reported error instead of retrying forever; remove either line to opt back into upstream's defaults.
